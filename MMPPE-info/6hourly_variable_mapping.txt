================================================================================
MMPPE 6-HOURLY INSTANTANEOUS OUTPUT -- MAPPING TO CESM/CAM6 (MG2/MAM4) FIELDS
================================================================================
Source protocol: MMPPE-info/MMPPE.md, "Model Output Variables" ->
  "6-hourly Instantaneous" and "6-hourly Instantaneous (optional)".
Reference for CESM field names/descriptions: MasterFieldList.txt (repo root),
cross-checked against addfld() calls in the actual Fortran source where
MasterFieldList.txt was insufficient or silent (noted per-entry below).

IMPORTANT CAVEAT ON MasterFieldList.txt: it contains ZERO fields with "MODIS"
in the name, meaning it was generated from a build with COSP disabled. All
"modis_*" mappings below (the entire optional table) were instead verified
directly against src/physics/cam/cospsimulator_intr.F90's addfld() calls,
which ARE present in this checkout (added in commit 57bc5465, "Add COSP
MODIS LWP/IWP joint histograms and CFODD warm-rain diagnostics"). Those
fields only appear in actual model output if the run is configured with
-cosp and the MODIS simulator sub-package turned on.

MATCH KEY:
  EXACT       - same physical quantity, same or directly convertible units
  CLOSE       - same quantity but with a caveat (weighting, band, phase, etc.)
  APPROX      - meaningfully different quantity used as the nearest stand-in
  DERIVED     - not a single field; computable via a stated post-processing
                recipe from existing CAM output
  NONE-BEST   - no native CESM field or straightforward derivation exists;
                entry gives the best available proxy/recipe anyway, per
                explicit instruction to always propose something rather than
                leave it blank. Treat these as starting points for custom
                diagnostic code, not off-the-shelf answers.

MMPPE Variable:   aerosol_extinction_355nm
Description:      Aerosol extinction @355nm
Unit (MMPPE):     m-1
CESM Field:       EXTINCTUV
Match:            APPROX
Notes:            CAM computes aerosol extinction natively only at 550nm
                  (EXTINCT), 350nm (EXTINCTUV), and 1020nm (EXTINCTNIR) --
                  no 355nm band. EXTINCTUV (350nm) is the nearest available.
                  "day only" (masked to daylit columns); day+night variant
                  EXTINCTUVdn also exists. Protocol says model output must be
                  interpolated to 8 fixed altitudes in post-processing
                  regardless of which band is used.

MMPPE Variable:   ANG_440nm_670nm
Description:      Angstroem parameter 440nm-670nm
Unit:             1
CESM Field:       ANGSTRM (new field, 400nm-700nm), or derive from AODUV
                  (350nm) and AODVIS (550nm) as a fallback
Match:            NONE-BEST
Notes:            A new ANGSTRM field was added to src/physics/rrtmg/
                  radiation.F90 (see ppe_changes_incorporated.txt section
                  7c) -- computed as a real model diagnostic between the
                  400nm and 700nm SW bands (RRTMG bands idx_sw_diag+1/
                  idx_sw_diag-1), using the exact formula/band choice from
                  MMPPE-info/radiation.F90 (a legacy E3SM radiation driver),
                  which is a real, previously-validated AeroCom-submission
                  diagnostic -- not tuned to match this protocol's
                  440-670nm request specifically. It brackets a similar
                  (broader) range, so it's arguably the better proxy of the
                  two options here, but still not exact. The older
                  AODUV/AODVIS-derived recipe (Angstrom =
                  -ln(AODVIS/AODUV)/ln(550/350), 350-550nm) remains
                  available as a fallback if 400-700nm is judged too wide.
                  A second native field, ANGSTRM_550_865 (~550-865nm, see
                  ppe_changes_incorporated.txt section 7e), also exists now
                  but is a worse match here than ANGSTRM -- 440-670nm sits
                  closer to 400-700nm than to 550-865nm. ANGSTRM is
                  day-only and not on by default; add via fincl.
                  Not yet validated against real model output.

MMPPE Variable:   TAU_2D_MODE_KS_550nm / _AS_ / _CS_ / _KI_ / _AI_ / _CI_

CESM Field:       AODDUST, AODSO4, AODPOM, AODSOA, AODBC, AODSS (all @550nm)

                  breakdown satisfies the intent of this row, that's the
                  real, already-implemented option; the mode-based version
                  the protocol literally asks for does not exist and would
                  need new code in modal_aer_opt.F90.

MMPPE Variable:   ND_INCL_CT
Description:      Cloud-top in-cloud cloud droplet number concentration
Unit:             m-3
CESM Field:       ACTNL (grid-mean; divide by FCTL for true in-cloud value),
                  or ACTNL_OVL / FCTL_OVL for the overlap-weighted variant
Match:            CLOSE
Notes:            ACTNL ("Average Cloud Top droplet number") is computed in
                  micro_mg_cam.F90 as icwnc_grid * liqcldf_grid at the FIRST
                  cloudy level found scanning down from top_lev -- a
                  grid-box-mean value (divide by FCTL for the true in-cloud
                  value the protocol name implies), with no cloud-overlap
                  weighting across layers.

                  ACTNL_OVL was added alongside ACTNL (not replacing it) to
                  give a second option that properly accumulates
                  contributions from every cloud-top-exposed layer using a
                  maximum-random overlap assumption, adapted from
                  MMPPE-info/output_aerocom_aie.F90's cloud_top_aerocom
                  subroutine -- the algorithm MMPPE.md's "Cloud-top
                  calculation" note (MMPPE-info/cloud-top-calculation.F90)
                  actually specifies, and a materially better approximation
                  when clouds are broken/multi-layered. Same grid-mean
                  convention; divide by FCTL_OVL for the in-cloud value.
                  Not yet validated against real model output -- see
                  ppe_changes_incorporated.txt section 7b.

================================================================================
SUMMARY
================================================================================
Of ~79 variables across both tables:
  - ~35 have an EXACT or CLOSE native CESM field match
  - ~16 are DERIVED (computable from existing output via a stated recipe)
  - ~10 are APPROX (a real but meaningfully different field used as proxy)
  - ~13 are NONE-BEST (no native field or clean derivation; best-effort
    proxy/recipe given, but genuinely need new code or an offline recipe not
    implemented anywhere in this codebase)

  (Updated after adding the CCN7/S=0.3% diagnostic bin to
  src/physics/cam/ndrop.F90: CCNS_0.300 moved APPROX->EXACT;
  CCN_BURDEN_0.300 and CCN_BL1_0.300 moved APPROX+DERIVED->DERIVED.)
  - The entire optional MODIS table (13 vars) additionally requires COSP
    enabled at build/run time, which is off by default.

Recommend treating this file as a first-pass reference, not a final
data-request spec -- several NONE-BEST / APPROX entries (CN_BURDEN, N70,
N100, LTS, CTT, CBH, PM1/PM10, the mode-based AOD split) would need new
Fortran diagnostic code before they could actually be output, and the
"aci-baseline" cloud-top-calculation document MMPPE.md references (not in
this repo) may already specify preferred recipes for several of these.
